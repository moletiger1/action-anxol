# v0.4仕様の合成データ検証

[仕様v0.4](../../docs/superpowers/specs/2026-10-09-action-requirements-design.md)のレビュー指摘1〜3を、製品コードから独立した小さい状態モデルで確認します。**本番実装でも、外部事業者の能力を検証するコードでもありません。**

## 実行

リポジトリルートで実行します。Node標準の `node:test` / `node:assert/strict` だけを使うため、npm依存の導入やサーバー起動は不要です。

```bash
node --test scripts/spec-validation/*.test.mjs
```

実行を確認した環境はNode.js **v26.8.1**。Node.js 24での実行は未確認です。

## モデルの前提と限界

- 署名/本人一意性/利害独立性/所持証明/外部照合は `synthetic-*` のラベルと明示的な成功フラグで仮定します。暗号署名を検証していません。実メール/個人情報/口座/カード/秘密鍵は扱いません。
- CASはメモリー内の状態/版チェック、台帳rootは版カウンターの代用です。同期呼出しの順序で競合の先後を確認しており、実DB・合意基盤・銀行間の原子的実行やマルチプロセス同時実行は未検証です。永続化・復元・銀行管理画面等の迂回不能も未検証です。
- 候補モデルのA/B、N/root、選挙結果、支出の他条件はfixtureです。票集計、円送金、正式契約、異議の外部裁定は実装していません。銀行UNKNOWNは照合前の保全を確認し、候補モデル自体には終端照合の実装がありません。
- 返金は単一募集/使途、本人別の集約権利、固定5人裁定パネルの仮定です。銀行結果は残額全額完了か実送金0円の失敗を扱い、銀行の部分完了は未対象です。24時間再試行期限、法的請求、外部権利保管、取消準備金の事業者固有ルールは未検証です。
- 返金の再試行では原操作payloadを変えず、別の最新外部権利contextを照合します。`prepareRetryContext` はその外部照合を成立したものとして与えるfixtureであり、実照合を行いません。同一操作のreceipt再送は返すだけで、新送金を行う意味ではありません。
- 現金不足時の `externalAdvance` は、外部立替と同額債務を仮定した記帳です。実際の資金調達・補填保証・債権回収ができるという意味ではありません。
- カタログの意味分類・候補変化・公開hashはfixtureです。AI検索品質を確認していません。通常審査/異議終了は暫定承認fixtureから始め、時刻は信頼済みの基盤時刻を入力する仮定です。成功3署名で再照合期間を完了し次競合で別期間を開始、同じ未完了期間の更新では延長しません。

検証成功を数値提案の承認や本番ゲートG-01〜05の解除に使いません。仕様変更時には対応ケースとこの検証範囲を更新してください。
