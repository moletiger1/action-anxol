保存先は東京リージョンの `auth-security` DB。実行サービスアカウントの権限はそのDBに限定し、署名鍵も専用シークレットの参照権限だけを付与。状態は1ドキュメントに件数と窓の終了時刻を保存し、パスワード・Cookie・IPを保存しない。

制限の単位は共有デモアカウント全体である。第三者が試行枠を使い切ると、未認証の利用者も次の窓まで待つ。署名済みの8時間セッションは影響を受けない。一般公開の個人アカウント認証にはユーザー別の認証基盤が必要であり、この実装をその代替とはしない。

## 対応事項

### 1. 中：Basic認証に試行回数の制限がない

**場所：** `web/src/proxy.ts:15-25`、`scripts/deploy-cloud-run.sh:12`

認証失敗時は毎回401を返すだけで、失敗回数の記録、待機時間、回数制限がない。配備スクリプトはCloud Runへの未認証接続を許可し、アプリのBasic認証で保護する構成である。

外部からパスワードの推測を繰り返せる。弱い、または使い回したパスワードの場合に閲覧制限が破られるリスクがある。現在のパスワード強度は調べていないため、実際に推測可能とは断定しない。

**確認：** ローカルの本番ビルドに誤認証を20回送信し、すべて401だった。コードにも制限処理がない。公開環境への大量試行は行っておらず、クラウド側に別途設定された制御の有無は未確認。

**対処：** 検証者だけに絞れる認証付きの入口、または複数インスタンスで共有される試行制限を設ける。入口だけで制限する場合、Cloud Run標準URLが迂回路にならない設定も必要。Basic認証を維持する間は十分に長いランダムなパスワードを使う。プロセス内のカウンターだけでは最大2インスタンス間で制限を共有できない。

### 2. 低：外部サイトへの画面埋め込みを禁止していない

**場所：** `web/next.config.ts:3-5`、`web/src/proxy.ts:30-32`

ローカル本番ビルドの認証済み200応答に、`Content-Security-Policy` と `X-Frame-Options` がない。コードにも設定がない。ブラウザーが埋め込み先に認証情報を送る条件では、攻撃者が画面を重ねて操作を誘導するクリックジャッキングへの防御がない。

現在の操作はブラウザー内のデモに限定され、実決済や共有DBの書き換えには接続していないため、現状の影響は限定的。実ブラウザーでのクリック誘導は未検証。

**対処：** 埋め込み用途がなければ `Content-Security-Policy: frame-ancestors 'none'` と `X-Frame-Options: DENY` を追加する。一般的な防御強化として `X-Content-Type-Options: nosniff` も検討する。CSP全体を設計する場合はNext.jsのスクリプト動作と整合させる。

### 3. 低：開発用依存にellipticの既知の問題が残る

**場所：** `contracts/package.json:15`、`contracts/package-lock.json:1848`

`npm audit --package-lock-only --json` は低11件を報告した。独立した11種類の問題ではなく、`elliptic@6.6.1` の1件のアドバイザリーと、その依存元への波及である。

依存経路は `hardhat-toolbox-viem → hardhat-verify → @ethersproject/abi → … → @ethersproject/signing-key → elliptic`。Webの依存には含まれず、SolidityにJavaScriptのellipticが組み込まれるわけでもない。現在のコードから問題の署名処理への到達は確認していない。

[GHSA-848j-6mx2-7j84](https://github.com/advisories/GHSA-848j-6mx2-7j84) は特定条件下でのECDSA署名の不備と秘密鍵露出の可能性を説明し、修正版はないとしている。今回の監査結果も `fixAvailable: false`。

**対処：** 開発ツールの更新・依存の除去でこの経路を解消できるか検討する。対応まではこの経路で実資金の鍵を使った署名を行わない。`npm audit fix` で解決できるとは扱わない。

## 検証を妨げるテストの不具合

これは確認済みの送金脆弱性ではなく、セキュリティ検証の信頼性に関わる問題である。

1. `contracts/test/ConsultationVault.t.sol:85` など9か所の日本語文字列に `unicode` 接頭辞がない。元の `npm run test:solidity` は `ParserError: Invalid character in string` で停止し、テストは走らない。該当リテラルを `unicode"..."` にする必要がある。
2. 同ファイルの726行・731行からの `vm.prank(...)` は、期待エラーを組み立てる `vault.pausedUntil()` 呼び出しに消費される。構文だけ補正した一時コピーでは43件成功・1件失敗で、期待する `Paused(...)` に対し `NotDeliberator()` が返った。getterの評価後に `vm.prank` を置く必要がある。

一時コピーだけで上記2点を補正した後は **44件成功**。返金のfuzzテストは256回実行された。対象のコントラクト本体は変更していない。元のリポジトリでは不具合が残っているため、「既存テストがすべて成功」とは扱わない。

## 確認できた防御

| 項目 | 結果と範囲 |
| --- | --- |
| 公開環境の未認証アクセス | `https://action.anxol.com` とCloud Run標準URLで、トップ・favicon・存在しない静的JSへの要求が401。誤ったBasic認証、`x-middleware-subrequest` とRSCヘッダーを組み合わせた要求も401 |
| ローカルのBasic認証 | 既存 `web/scripts/check-basic-auth.mjs` が成功。正しい認証でページ・実在するJSにアクセスでき、無認証・誤認証は拒否。認証設定なしではページ・静的パスとも503 |
| キャッシュと通信 | ローカル認証済み応答と公開環境の401応答は `private, no-store`。両公開ホストのHTTP接続はHTTPSへ302。公開環境の認証済み応答は未確認 |
| コントラクト | 登録先への支払い、役割・承認数、予算上限、異議、期限、本人への返金をコードと上記テストで確認。送金系に `nonReentrant` と残高差分の検査あり |
| 秘密情報 | 参照可能な3コミット・重複除外170blobと現在のログに、秘密鍵・代表的なトークン・文字列代入された秘密情報のパターン一致なし。独自形式・エンコード済み値・参照不能な履歴は保証対象外 |

Webの入力はReactの文字列として描画され、`dangerouslySetInnerHTML`、`eval`、独自のAPI・Server Actions・SQL・決済APIへの接続は見当たらなかった。資料選択はファイル名等を画面内に保持するだけで、ファイル本文の送信・サーバー保存は行っていない。未実装のDBにRLSがないことや、デモのサインイン省略を認証脆弱性としては数えていない。

下書き・プレビュー・弁護士提案は `localStorage` に保存する仕様。サーバーから他人に配信されるものではないが、共用ブラウザーでの利用者分離や保存期限はない。実際の個人情報を扱う前には、保存・削除・閲覧権限の設計が必要。

## Next.jsの追加修正予定

現行は `next@16.3.6`。Webの `npm audit` は既知の警告0件だった。ただし公式は **2026年9月30日に16.3.7 / 15.5.27を公開予定** とし、Critical 1件を含む9件の修正を予告している。影響条件と対象バージョンの詳細は公開待ちなので、現行アプリにCriticalが成立するとは断定しない。[Next.js公式予告](https://nextjs.org/blog/upcoming-nextjs-security-release-september-2026)

公開後にアドバイザリーを確認し、対象なら修正版への更新、認証テスト、再ビルド、再配備を行う。

## 実施条件と限界

依存はロックファイルから `npm ci --ignore-scripts` で準備。Webの `npm run build` は成功した。実行環境はNode.js 26.8.1で、Webが指定する24.xとは異なるため、24.xでの再検証は残る。

公開環境では少数のGET要求のみ実施し、クラウド設定・IAM・実パスワードの取得、負荷試験、実取引は行っていない。秘密情報検査はパターン検索であり、専用スキャナーや全履歴の漏えい調査を代替しない。コントラクトも形式検証・網羅的fuzz・実トークンとの統合試験ではない。役割分離はアドレス単位で、現実の同一人物・結託までは防がない。
