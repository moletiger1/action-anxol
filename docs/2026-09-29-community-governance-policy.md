# 集団訴訟.jp（仮）：参加者が審議し、資金を共同管理するサービス方針

2026年9月29日。現行の方針案。

ユーザーが合意した原則は「固定の運営会社なし・参加者による審議あり」。当事者・情報・予算が集まってから弁護士の提案を募る。ここまでが合意済みの方向性であり、以下の人数・期限・決定ルール等は検討用の初期案。画面とローカル用コントラクトの試作はあるが、互いに未接続で、実資金の募集・コントラクトのデプロイ・外部への依頼は未実施。

追加の必須要件：ユーザーは「管理者もルールを破れない」ことを明示した。共同資金の保管・支出・返金を、通常のWebアプリの管理者権限だけに委ねる構成は採用しない。管理者にも迂回できないコントラクト上の制約を設計の中心とする。コード外の事実判断・銀行資金・受取人による支出まで自動保証するという意味ではなく、その境界は第7節に記す。

## 1. サービスの目的と役割

**当事者が案件を提案し、仲間と相談予算を集め、専門家の説明を受けた参加者が弁護士の提案を比較し、希望者が正式に依頼する。**

案件は共通の公開条件に沿って投稿できる。開発者や最初の作成者に、事件ページの独占権、他人の投稿の恒久的な拒否権、弁護士選定・共同資金移動の単独決定権を与えない。日常業務を担う人は存在するが、任期・担当範囲・支出権限を明示し、交代できる構成にする。裁判・法律相談・個人情報管理に関する現実の責任がなくなるという意味ではない。

| 役割 | 担当 | 単独ではできないこと |
|---|---|---|
| 案件作成者 | 自分の事実・資料・相談目的の入力、募集の共有、更新 | 事件ページの独占、自分が当事者の異議裁定、共同資金の引出し、他人の委任 |
| 案件参加者 | 当事者登録、任意の拠出、審議への協力、個別依頼の判断 | 拠出額に応じた決定権の購入、他人の参加の強制 |
| 審議役 | 提案比較、事前に定めた範囲の支出承認、別途選任された場合の異議確認 | 自分が紛争当事者の異議裁定、応募弁護士との利害を隠した選定、法的権利の確定 |
| 弁護士・説明役 | 法律上の論点の説明、相談・受任条件の提示、受任後の業務 | 応募者自身による採択審議、未委任者の代理 |
| 技術・本人確認・保管の担当 | ソフト提供、証明の発行、必要資料の限定保管、障害対応 | 開発者権限での資金回収、投票結果の書換え |

参考にした記事は、専門家の説明を受けた構成員による審議と、コントラクトによる予算執行を組み合わせる制度提案である。本書はその考え方を任意参加の案件に応用した案であり、記事の仕組みが訴訟支援サービスとして実証済みという意味ではない。[契約民主主義の記事](https://alis.to/sg42/articles/azDdvM7lLXYp)

## 2. 案件の開始から相談・訴訟まで

### ① 作成と仮公開：一律の第三者による事前承認は設けない

作成者が入力するのは、何が起きたか、自分との関係、対象者、手元の資料、求める対応。違反条文、勝率、慰謝料の適正額は入力させない。必要事項から募集文案を作り、作成者が事実と原資料を照合して確定する。

従来の「5名中3名で掲載承認」は撤回する。掲載前の審議協力者の母集団・選任根拠が未定だったためである。必要事項・公開用の根拠・重複候補の確認を経て「投稿者の申告／未検証」として仮公開し、参加希望を集められる案とする。公開は事実の認定・勝訴見込み・集金許可を意味しない。

公開条件は、出来事と募集目的の明示、根拠と未確認事項の区別、個人情報・脅迫等を公開しないこと。自動チェックで内容の真偽や適法性を保証しない。原本は非公開とし、公開文章をチェーンへ永久保存しない。通報・訂正・表示保留・再確認の経路と、その担当・権限を公開前に定める。

**事件ページと募集案を分ける。** 同じ出来事のページは共有し、その中に対象者・相談目的・予算・依頼方針の異なる募集案を置ける。最初の作成者に他の募集案への拒否権を与えない。追加情報・訂正理由を記録し、既存投稿の勝手な上書きも認めない。

### 重複防止：同一IDは拒否し、類似案件は確認へ回す

| 段階 | 動作 | 担当 |
|---|---|---|
| 作成途中 | 組織、出来事の種類、発生期間、公表資料から類似候補を提示。既存事件への参加・募集案追加を案内 | アプリの検索。必要ならAIで補助 |
| 同一IDの登録 | 登録済み事件IDによる別の事件ページ作成を拒否 | 共通レジストリのコントラクト |
| 類似だが未確定 | 既存事件を選ぶか、別事件である理由を記録して仮登録。類似度だけでは最終拒否しない | 作成者 |
| 同一事件と確定 | 作成者の同意または異議手続の裁定に従い、別IDから共通IDへの参照を登録。以後の作成・募集開始時にも参照先を使用 | 有効な決定をコントラクトが検証・反映 |
| 誤統合への異議 | 根拠付きの再確認と参照の訂正。変更履歴を残す | 事前に定めた再確認手続 |

事件IDは共通レジストリで管理する識別子。法人番号等の組織情報、事件の種類、発生期間、公表資料は検索属性とするが、その単純な連結やタイトルのハッシュを現実の事件の一意性の証明にしない。発生日と公表日、同じ会社の別事件、複数社にまたがる同じ事件、追加公表を区別する。URL違いや言い換えによる重複は、同一ID拒否だけでは防げない。

実装中のコントラクトでは、最初の募集作成時に指定された `eventId` を工場へ登録し、後続の募集金庫を同じ `eventId` に紐付ける。作成者別の募集IDとは分離され、資金・予算・委任は合算しない。募集IDの下書き置換でも事件IDは変更できない。これは同一IDの複数募集を束ねる基礎であり、異なるIDの事件を同一と判定する機能や、同意に基づく別名統合・異議裁定は未実装。

コントラクトは、IDの重複登録拒否、確定した別名IDから共通IDへの参照、循環参照の禁止、判定権限・署名・期限の検証を担当する。画面を迂回した直接呼出しにも同じ条件を適用する。文章の意味やウェブ上の事実は外部で判断する必要があり、有効な署名でも判断の正しさまでは保証されない。[Ethereumのオラクル解説](https://ethereum.org/developers/docs/oracles/)

**争われた同一性の裁定者は未確定。** 候補は、当該事件・作成者・相手方と利害関係のない、事前登録された確認協力者。実在する母集団、選任・交代、定足数、判断期限、再確認を定めるまで、AIや開発者の鍵だけで強制統合する機能は有効にしない。「5人」という人数だけで解決済みとしない。固定運営会社を置かないことと、争いの判断主体をなくすことは異なる。

類似判定や無根拠の通報だけで既存案件の資金を凍結しない。正式な異議手続で保留対象となった新しい募集案は、解決前に集金を開始しない。期限内に解決できなければ参加希望のみの状態を維持し、再確認を案内する。異議の受理条件・判断期限は事前に公開する。

事件ページをまとめても、予算・委任・非公開資料を自動合算・移転しない。参加人数は本人確認と同意の範囲で重複を除き、除けない数字を合算して当事者総数と表示しない。この制約が及ぶのは共通レジストリを使うサービス内であり、他のチェーンや独自サービスへの投稿は禁止できない。

例：「タイムズカー情報漏えい」と「パーク24の漏えい被害」は、公表資料と出来事を照合して同じなら共通ページへ案内する。個人会員と法人会員で相談目的が違う募集案は、同じ事件ページ内に併存できる。

### ② 当事者と予算を集める

公開ページには、対象者、根拠、法的判断前であること、登録人数の定義、目標予算と使途、期限、未達・相談不能・残金の扱い、今後の選定ルールを表示する。

当事者登録と支援だけの参加は区別する。登録人数、本人・関係性の確認人数、資料の確認人数、拠出人数を混同しない。登録や入金は正式委任としない。

資金募集を始める前に、審議の母集団・選定ルール、本人確認、支出権限、契約主体、異議手続を確定し、予算と返金方式が実装・決済手段と一致することを確認する。資金は募集案ごとのコントラクトで分離する構成を技術案とする。一般の銀行預金・カード決済を、そのままパブリックチェーン上で扱えるとは想定しない。利用する資産、円換算、受取方法、手数料・値動き等は集金前に確定する。コントラクトは送金元・送金先・金庫の残高変化が指定額と一致する資産だけを扱い、手数料控除型やリベース型の資産は取引を拒否する。実資金では選定した資産とネットワークでこの条件を確認する。

### ③ 弁護士の提案を募る

人数、資料の種類と確認状況、被害概要、求める対応、集まった予算を、個人が特定されない範囲で示す。弁護士は自ら案件を選び、費用・対応範囲・必要資料・担当体制・条件・時期を定型書式で提案する。

弁護士の登録・本人確認は行う。原本・個人情報は参加者が指定した相手に、利益相反確認等に必要な手順を経て限定共有する。全応募者に全員の原本を開示しない。第三者が書いた応募内容の自動採点で担当弁護士を決定しない。

応募がない、必要額に届かない、条件が合わない場合には、事前の期限とルールに従い再募集または終了する。後から無断で予算・用途を変えない。

### ④ 専門家の説明を受け、共同相談先を決める

共同相談先の審議役の母集団は、その募集案に参加する当事者のうち、本人・関係性の確認を終え、審議への参加意思を示した人とする。受任候補との利害関係を除いて抽選する案。従来の「5名中3名」は採用済みのルールではなく、人数・定足数・決選手順は集金前に確定する。参加希望者からの抽選なので、全参加者を無偏りに代表するとは限らない。無作為性の検証方法、辞退・欠員補充も事前に定める。

候補の弁護士は同じ質問に平易な言葉で答える。必要に応じて、受任候補と利害関係のない説明役の弁護士が、争点・費用の前提・判断できない点を説明する。説明役の費用は、最初から明示した相談予算内に含める。候補自身が自分の提案の採否を投票しない。

比較表と参加者からの質問を踏まえ、拠出前に示した決定ルールで共同相談先を選ぶ。定足数や必要な賛成が得られなければ、事前の期限・再審議・終了または再募集の条件に従う。無回答を賛成として扱わない。

採択対象は共同資金で行う相談・初期調査とする。署名付きの決定、相談範囲、予算、受取人を記録し、事前の支出条件に合致するときだけ支出可能にする。説明資料の一般公開版と、参加者向けの非公開資料を分ける。

### ⑤ 個別委任と、その後の資金募集

相談結果と収支を参加者へ報告する。弁護士が実際の対象者・条件・費用を示し、希望する人が個別に正式依頼する。審議役の多数決で全員の委任・和解・請求放棄を決めない。

追加の調査・訴訟費用が必要なら、使途と見積もりを示して別段階の募集と同意を行う。相談の結果として見送る場合も終了できる。

## 3. スマートコントラクトに任せることと、残る役割

| 対象 | コントラクトで扱う内容 | 外側に残る仕事 |
|---|---|---|
| 資金 | 案件別残高、上限、期限、権限、支出履歴 | 資産の選定、円での受取り、税務・法的整理 |
| 未達・未使用資金 | 所定条件で返金請求できる状態への遷移 | 請求トランザクションの送信、利用料、鍵紛失への対応 |
| 選定 | 登録済み審議役の署名・投票・定足数の検証 | 一人一登録、当事者性、利害関係の確認 |
| 業務に応じた支払い | 合意した条件を満たした署名等に基づく段階支払い | 約束された相談・調査が実施されたかの確認、異議の審理 |
| 記録 | 必要最小限の決定・支出記録 | 非公開資料の保管、訂正・削除、問い合わせ |

コントラクトは時刻が来れば自分から動くものではない。返金・支払いには、利用者等のトランザクションや実行サービスが必要となる。公開チェーン上に住所、免許証、原本メール、訴訟資料を保存しない。ウォレットと案件の結び付き自体が公開され得る点も説明し、必要なプライバシー方式を選定する。[Ethereumのコントラクト解説](https://ethereum.org/developers/docs/smart-contracts/)、[プライバシー](https://ethereum.org/privacy/ethereum)

「相談が実施された」「資料が本物」などの外部の事実には、証明・判断を提供する人やサービスが必要になる。署名が有効でも、その署名者が正しい判断をしたことまでコードが保証するわけではない。[外部情報とオラクル](https://ethereum.org/developers/docs/oracles/)

現行デモコントラクトでは、異議裁定役を審議役・支出確認担当と兼任できず、裁定役本人の拠出も拒否する。これはオンチェーンで検査できる役割分離であり、現実の利害関係の確認・選任・交代手続を代替しない。

投票で支出を止めても、すでに完了した業務に対する報酬債務を消せるわけではない。契約上の支払条件、未使用予算の停止、異議がある支出の扱いを対応させる。支払条件に争いがある場合の独立した確認役、期限、既存の法的手続への接続を、拠出前に定める。

## 4. 最初の版の機能と、公開前に解く課題

### 最初の5機能

1. 質問に答えて案件を作成し、公開用の下書きを確認する。
2. 類似事件の候補提示、共通事件ページ、重複ID拒否、同一性への異議を扱う。
3. 当事者登録・資料の確認状況・予算募集の現在地を表示する。
4. 弁護士の提案、説明、質問、審議・選定結果を比較できるようにする。
5. 資金の条件・残高・支出・返金と、相談後の個別依頼を管理する。

### 公開・集金前の必須設計

| 課題 | 必要な決定 |
|---|---|
| 一人一登録と資格証明 | 複数ウォレットによる重複投票を防ぐ方法、確認担当の選任・交代、証明の取消し・異議 |
| 審議役の確保と利害関係 | 初期協力者の募集、欠員補充、謝礼・財源、相手方や応募者との関係、買収・談合の申告対応 |
| 資金と契約 | 使用資産、支出権限、契約・請求の名義、決済費用、返金の実行、受任・紹介と料金の関係 |
| 紛争・障害 | 支払保留と解決期限、緊急停止、バグ、鍵紛失、ルール変更、改修権限と資金への影響 |
| 機密情報と公開画面 | 保管責任者と閲覧範囲、削除、フロント画面の公開基準、通報・停止と代替アクセス |

これは「まだ人手があるから実現できない」という結論ではない。固定運営者に集中していた役割を、誰にどの条件で担わせるかを定める課題である。確認担当や審議役を開発者が恒久的に自由選任できるなら、権限を分散したとは表示しない。

最初の審議協力者や確認担当は自然発生しない。立上げ時は実名・役割・任期・選任理由を明らかにした協力者を募り、交代・追加の手続きを設ける。初期の委嘱主体と権限が残る期間も明示する。独立した協力者が揃う前は、試作・模擬案件で手順を検討し、実資金の受付に進めない。

コントラクトの検査・監査と、運用の制度確認は集金前に行う。固定の会社を置かないことや自動実行だけで、法律上の役割・責任・規制が消滅するとは扱わない。資産を動かせる実際の権限や、弁護士との接続・料金の実態を確認する。[金融庁の指針](https://www.fsa.go.jp/common/law/guide/kaisya/16.pdf)、[日弁連の指針](https://www.toben.or.jp/know/iinkai/hibenteikei/pdf/kaiki_no_70_02.pdf)

## 5. 収益・集客とタイムズ第一号

中央の運営会社の利益を前提にせず、開発・保守・審議支援等のサービス提供者が、透明な予算提案を通じて対価を受け取る構成を検討する。初期試行では運営手数料を取らず、必要な外部費用と初期協力者の負担を明示して測定する案。継続運営の財源には任意支援やソフト利用料等が候補になるが、事件紹介・受任成約の対価にならないことを確認してから採用する。独自トークン発行や、賠償金への投資リターンは初期案に含めない。

集客では「同じ問題の仲間と相談予算を集め、参加者の審議で次の行動を決める」を説明する。技術を使っていることだけを、安全性・勝訴・返金の保証として宣伝しない。案件ページを共有し、人数と予算、審議・会計の透明性を示す。参加者本人の氏名や参加履歴は共有画像に含めない。

タイムズ第一号では、ユーザーを作成者とし、既存の通知メールは非公開の根拠資料として扱う。本人の漏えい項目は未確定であり、その確認と法的評価を済んだものとして扱わない。公開条件と重複候補を確認して参加希望を集める。募集案の資金・選定・異議ルールの確定後に予算募集を始め、人と予算が集まってから弁護士の提案に進む。

直近の成果物は「案件作成」「案件ページ」「審議と弁護士提案の比較」の画面案。資金を扱わない試作で、法律知識のない協力者が各自の役割を理解できるかを先に確認する。チェーン選定・実資金コントラクト実装は上記の権限・資金・例外処理の決定後に行う。

関連資料：[タイムズ案件の証拠・収集方針](2026-09-29-collective-claims-policy.md)。従来の代表者選定・運営審査案は、この方針によって更新する。

## 6. 集まった資金の使途と、回収金の精算案

2026年9月29日追記。ユーザーが前節までの方針を了承し、支出・成功後の分配の検討を依頼したことに基づく追加提案。この節の具体条件は運用・契約条件として未承認・未実装。返金端数については、後段にローカル用コントラクトで採用した技術仕様を記す。まず個々の当事者が弁護士に委任する構成を想定する。特定適格消費者団体による被害回復制度を、このアプリが当然に利用できるとは扱わない。[消費者庁の制度案内](https://cocolis.caa.go.jp/organization/index.html)

### ① お金を三つに分ける

| 区分 | 集める時期・用途 | 受取先と残金の扱い |
|---|---|---|
| 共同相談費 | 弁護士募集前から、用途・上限・期限を決めて募集。相談、初期調査、必要な資料整理・説明のため | 採択された弁護士や承認済みの作業担当へ。未使用残金は精算して拠出者へ返す |
| 訴訟費用 | 相談結果・見積もりを示した後、正式に依頼する人の同意を得て別募集。着手金、裁判所への費用、鑑定等 | 弁護士、裁判所、鑑定人等へ。依頼していない人に負担させず、未使用残金は別途精算 |
| 回収した賠償金・和解金等 | 相手方から実際に支払われた後に処理。募金・サービス売上と混ぜない | 判決・和解・委任契約等に従い権利者ごとに精算。作成者や支援者への一律配当にはしない |

共同相談費の段階では、受任者未定でも「何を相談するために、最大いくら集め、いつまでに相談先が決まらなければ終了するか」を示す。弁護士の提案が予算を超えれば、自動増額せず、範囲の見直し・追加同意・終了を選ぶ。相談を見送る結論も成果として扱い、既に実施した相談を無償扱いしない。

被害当事者の費用拠出と、第三者の応援支援を表示上・帳簿上で区別する。初期案では第三者の支援に投資リターン・賠償金の持分・訴訟方針の決定権を付けない。未使用部分は募集時の条件で返金する。資金を多く出した当事者にも、それだけを理由に賠償金や議決権を上乗せしない。投資型の訴訟資金提供を行うなら別の制度設計とし、この支援枠へ混在させない。

### ② 誰が決め、誰に支払うか

毎回全員で支払投票する方式は遅延しやすく、作成者一人に預ける方式は資金権限が集中する。初期案は、**審議で予算と契約条件を承認し、条件を満たした支払いを実行する方式**とする。

| 担当 | 権限・責任 |
|---|---|
| 弁護士・作業担当 | 業務、総額、税込額、実費、期日、支払条件を提案。自分への支払いを単独承認しない |
| 当該募集の審議役 | 本人・当事者性を確認した参加希望者の母集団から前節の手順で選任。共同相談先、予算内訳、支払条件を審議。名簿・選任条件・定足数を集金前に確定する |
| 正式依頼する各当事者 | 自分の委任、負担額、回収金からの控除、追加費用、和解等に同意。審議役の決定だけで委任した扱いにしない |
| 契約上の確認担当 | 支払先と独立した担当が請求・実施記録を照合し、事前条件に沿う支出を証明。裁判結果への賛否を理由に既発生の報酬を止めない |
| コントラクト／決済担当 | 権限、予算上限、支払先、支出ID、重複支払、期日を検証して実行。銀行送金の実行者・権限・証跡は別途明記 |

契約書には実在する依頼者と受任者を記載し、「DAO」の表示だけで契約主体を曖昧にしない。共同相談に代表窓口を置く場合も、契約当事者・代理権・費用負担を明記し、窓口担当に全員の和解権限や自由な出金権限を与えない。

支出先は採択した弁護士、必要な鑑定・資料整理の担当、裁判所や決済事業者等。作成者への案件作成ボーナス・紹介歩合・賠償金の自動取り分は初期案に設けない。作成者が資料整理等を担う場合は、実作業・上限額・利益相反を事前開示し、本人を採択・検収から除外する。募集済みの法律相談費を事後的に広告費や開発費へ流用しない。

契約時の着手金、相談実施後の残額、提出等の段階ごとの支払いを提案書で比較する。全てを後払いと強制せず、前払金・実費預り・確定報酬を区別する。法律相談と法的評価は弁護士が担当し、一般の審議役が法律判断を販売する構成にしない。報酬・費用・精算方法を委任契約で明示する必要がある。[愛知県弁護士会の費用解説](https://www.aiben.jp/soudan/bengoshihiyou/)

### ③ 回収後は各人の精算明細を作る

「勝訴」と「現金の回収」を別の状態として表示する。初期案の弁護士募集条件は、金銭請求の成功報酬について実回収額を算定基礎とし、税、対象となる元本・利息等、分割入金時の計算、報酬の発生・支払時期まで提案に明記させる方式。これはサービスが希望する契約条件であり、法律上の一律ルールや現在の相場ではない。非金銭的な成果の報酬は別に明示する。

1. 判決・和解等で誰にどの金額が帰属するかを確認し、本人・委任・受取先を照合する。登録や支援だけでは受取権を付与しない。
2. 実際の入金と帰属先を確認する。初期版は弁護士の預り金口座等から各本人の銀行口座へ精算する構成を推奨し、円を自動でトークン化しない。
3. 本人の回収額、契約済みの報酬、未精算実費、既払額、第三者支援による充当、費用の回収・返還を明細化する。同じ支出を共同資金と回収金から二重控除しない。
4. 本人へ精算明細を示し、異議のない支払可能額を契約・法令に従い速やかに送金する。争いがある部分は理由・期限・確認経路を示し、無関係な人の支払まで一律停止しない。
5. 送金済み・未受領・分割回収中を記録する。未受領金を作成者や残りの参加者へ自動再配分せず、連絡・保管・必要な法的処理を担当弁護士が扱う。

東京弁護士会の会規は、預り金の目的外使用の禁止、自己資金との区分、依頼者への通知・収支報告等を定めている。採用する弁護士の所属会の規則と契約も確認する。預り金口座を使えば不正が不可能になるという意味ではなく、入金照合・個人別残高・本人への明細を必要とする。[東京弁護士会の預り金会規](https://www.toben.or.jp/pdf/20170529_azukarikinkaiki.pdf)

基本の計算は、**本人への今回送金額＝本人に帰属する実回収額－契約に基づく今回の報酬控除－未精算の本人負担費用**。既払い費用をもう一度引かない。未使用拠出金の返還は別項目で加算できるようにする。控除が回収額を超える可能性は契約前に示し、不足分を口座から自動徴収しない。勝手にゼロへ丸めて債務が消えた扱いにもしない。

個人別の賠償・和解額が異なれば受取額も異なる。全体額だけの和解を検討するときは、弁護士が根拠ある個人別配分と費用控除を提示し、必要な本人の同意・権限確認を済ませる。総額を募金額や投票数で割らない。部分的な入金・和解・勝訴では対象者と対象額を特定し、未回収者の取り分を多数決で他人へ移さない。

**計算例（説明用の仮定。タイムズ事件の賠償見込み・報酬相場ではない）：** 本人の実回収5,000円、契約上の税込成功報酬1,000円、未精算の本人負担実費100円なら送金額3,900円。既に本人が相談費600円を負担していれば、他の費用・返金がない前提で、最終的な入出金差額は3,300円となる。「受取額」と「それまでの自己負担を含む収支」を両方表示する。

### ④ 残金・中止・不足を先に決める

| 状況 | 初期案の処理 |
|---|---|
| 目標未達・期限内に弁護士が決まらない | 契約済み債務がないことを確認し、残高を返金。決済・送金費の負担を募集前に明示し、無条件の全額返金と表示しない |
| 相談後に訴訟を見送る・敗訴する | 実施済み相談・契約上の着手金等は契約に従い精算。未使用分だけ返還。成功しなかったことだけを理由に全支出を取り消さない |
| 費用が余る・費用の還付等がある | 同じ使途・負担条件の会計内で、未払債務等を控除した返金原資を確定し、対象拠出額に比例して返す。使途指定の支援や別募集は混ぜない |
| 途中辞退・追加費用・控訴 | 既発生費用と契約上の解約条件を精算。未拘束部分の扱いを事前明示。追加依頼・負担増は対象本人の追加同意を取り、無同意の自動課金をしない |
| 入金不足・未回収・支払の争い | 満額を配った扱いにしない。部分回収の帰属と契約条件に従い精算。留保理由・解決期限を示す。確認担当不在時の補充手続も必要 |

共通費用は、同じサービスを受ける人について均等負担、特定の人だけに必要な追加作業はその人の負担を初期案とする。第三者支援の充当先・配賦方法も事前に明示する。費用の帰属が異なる募集を一つの残高に混ぜない。後から入った人の負担と、先に払った人への調整は参加前に示し、作成者の裁量にしない。

単純な例では、同条件で1,000円ずつ拠出した1,000人の共同相談費100万円から60万円を精算し、未払債務・別途費用がなければ、残り40万円を一人400円ずつ返す。端数処理と返金手数料も明示し、端数を作成者の利益にしない。

**初期実装の端数処理：** 返金額は拠出アドレスごとに按分して最小単位未満を切り捨てる。全員が請求しても、合計返金額と原資の差は拠出アドレス数未満の最小単位となり、その残額はコントラクトに留まり誰も請求できない。管理者への回収口は設けず、請求順による追加配分もしない。初期試作はこの動作だが、許容できる損失上限は未確定のため、実資金の受付条件としては未採用。拠出額は最小1トークン単位で拠出アドレス数に上限がないため、端数の価値は現状のままでは十分に制限されない。例として、6桁小数の資産で目標2,000単位を1最小単位ずつ集め、返金原資が1最小単位少ない場合、各人の按分額は0となり、返金原資のほぼ全額が請求不能になり得る。実資金を扱う前に、最低拠出額または別の按分方式を決め、最大残額を算出して決済費用とは別に表示する。

アプリ内の追加支出上限は、裁判所が命じる訴訟費用等の法的負担まで消すものではない。また、訴訟費用には弁護士費用が当然に含まれるわけではないため、「勝てば弁護士代が全部戻る」と表示しない。損害の一部として弁護士費用相当額が認められる場合とは区別し、回収時に実際の帰属を精算する。[裁判所の訴訟費用の説明](https://www.courts.go.jp/okayama/vc-files/okayama/2022/kansai/3_sosyou/02_baibaidaikinseikyuu.pdf)

### ⑤ 必要な画面と、自動化の範囲

最初の版では、募集ごとの「予算・支出・返金」と、本人だけに見える「回収・費用・手取り」の二画面を追加する。予算には支払先、用途、上限、支払条件、承認記録、実施・入金証跡を持たせる。本人画面には既払額を含む精算明細と異議の連絡先を表示し、銀行口座・実名・事件資料を公開チェーンへ記録しない。

コントラクトは承認済み予算の上限、支出IDの重複防止、権限、残金の返金条件を強制できる。勝訴判定、個人別の権利額、実際の銀行入金・送金、弁護士業務の履行は外部で確認する必要がある。円の預り金を扱う弁護士・決済担当の権限は隠さず表示する。回収金の全額オンチェーン分配は初期版に入れず、銀行入金を確認していないのに支払済みと表示しない。

サービス収益は第5節の方針を維持する。初期の運営手数料は0円案、将来の利用料・保守費等は使途と負担者を明記した別の料金として検討する。作成者・開発者への賠償金の自動歩合や弁護士報酬の自動分配は設けない。定額にすれば当然に適法という判断もせず、紹介・受任との実際の関係を確認する。[弁護士情報提供ウェブサイトに関する指針](https://www.toben.or.jp/know/iinkai/hibenteikei/pdf/kaiki_no_70_02.pdf)

## 7. 管理者にも資金ルールを迂回させない要件と海外事例

2026年9月29日の公開情報調査。サービス説明・募集実績・公開技術資料の確認であり、各社の現行デプロイ、管理鍵、全取引、監査範囲を独立検証したものではない。ブロックチェーン利用、トークンによる権利の表現、管理者による資金操作の排除は別々に確認する。

### 海外の先行例

| 例 | 一次資料から確認できた内容 | 今回の要件との関係 |
|---|---|---|
| Republic / Apothio ILO（米国） | 募集ページは2022年3月1日の終了、170投資家、約34.8万ドルの調達を表示。Avalanche上のトークン、条件付き資金解放、回収後のステーブルコイン分配を説明 | 訴訟投資の募集実績。ただし募集条件では法律事務所が資金を預かり、結果を通知・分配する。被害者が案件を作り共同統治するプラットフォームとは異なる |
| Liti Capital（スイス） | 訴訟金融会社の株式をLITIトークンで表現。2021年にBinance利用者の集団的な仲裁請求への資金提供を発表 | ホワイトペーパーはアップグレード可能なコントラクトと、創業者が保有する3署名者中2署名の管理鍵を記載。管理権限排除の先例とは扱えない |
| Ryval | Avalancheの公式発表にILOの関連サービスとして掲載 | 構想・発表は確認。今回の調査で現行の稼働案件・公開コントラクト・継続稼働は確認できず、終了したとも断定しない。Apothioの実績を独立した別サービスの実績として二重計上しない |
| Citadel / GOLDMOON（湾岸地域向け） | 公式サイトが弁護士入札・スマートコントラクトによる資金預託・段階払いを掲げる | 機能説明は近い。ただし現行デプロイ・監査・資金運用実績・管理者の迂回権限は未確認。欧米の実稼働例や安全性の証明としては扱わない |

米国の連邦クラスアクションにはRule 23の認証・対象となる和解の裁判所承認等があり、EUの代表訴訟指令では適格団体が消費者を代表する。米国・欧州を単一の制度として扱わない。ブロックチェーンでの投票・資金募集だけで、その手続要件を代替できるとは考えない。[米国連邦民事訴訟規則Rule 23](https://www.uscourts.gov/sites/default/files/document/federal-rules-of-civil-procedure.pdf)、[欧州委員会の制度説明](https://commission.europa.eu/law/law-topic/consumer-protection-law/representative-actions-directive_en)

**調査結果：訴訟金融とブロックチェーンを組み合わせた先行例は存在する。一方、被害者による案件作成・参加者による審議・管理者が迂回できない資金管理・回収後の個人別精算を全て満たす稼働サービスは、今回確認した公開資料では確認できなかった。存在しないことや世界初であることの証明ではない。**

### 今回の資金管理で固定する制約案

1. 管理者・作成者・開発者用の自由な出金機能を設けない。単なる複数署名の財布だけで済ませず、署名者が集まっても使途・金額・期限等の契約上の制約を迂回できないようにする。
2. 募集開始後、その募集の資金について管理者がコード・承認者選任ルール・支払条件を一方的に変更できない構成にする。改修は新しい募集契約として公開し、既存資金を強制移転しない。
3. 支払いは承認済みの業務・支払先・上限・条件に限定し、取引ごとの識別子で二重払いを拒否する。外部の履行確認に誰の判断を使うか、異議・欠員補充をどう扱うかも事前に固定する。
4. 未達・期限切れ等の返金条件を満たしたら、参加者が所定の取引を送って請求できる。管理者の承認や公式画面の存続を必須にしない。緊急停止にも目的・期限・解除条件を定め、無期限拘束の抜け道にしない。
5. 公開コードと実際のデプロイが一致すること、アップグレード・管理鍵・外部依存を確認する。バグ、確認担当の虚偽・共謀、資産発行者の凍結権限等を「管理者が出金できない」という一文で解消済みとしない。

強制できる対象は、そのコントラクトが保管する資産と、コードで表現・検証できる条件。弁護士への承認済み支払後の資金利用、円の銀行口座、判決・和解の解釈には外部の責任主体が残る。従来の円での回収・精算案にはこの信頼境界がある。利用者がそこまで管理者の裁量を排除したい場合は、受取・変換・分配方法を別途設計してから採用する。ブロックチェーン採用だけで全面的な不正防止を保証しない。
