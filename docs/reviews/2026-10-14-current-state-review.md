## 1. P1：落選した候補の辞退でも確定後の契約が止まる

**根拠：** S:264〜272（特に269）、S:255〜260。候補辞退・失効の時点表は、選ばれた候補と落選候補を区別していない。最終結果後・支出前の条件喪失でも、新規契約・支出を保留し、期限内に再選挙できなければ精算へ進む。

**具体例：** D+21日までに弁護士Aの選任が確定し、弁護士Bは落選する。契約承認期間中のD+22日にBが辞退署名を送る。現行の表をそのまま適用するとAとの契約も保留になるが、選任期限は既に過ぎている。Aも参加者の資格も有効なまま、落選者の単独操作で共同相談が終了し得る。

**最小修正：** 結果確定後の単なる辞退は対象候補を判定し、選任済みの候補の辞退にだけ契約・支出停止を適用する。落選候補の辞退は候補履歴の更新に留める。過去の選挙自体を無効にする不正の証拠は、単なる辞退とは別の異議条件にする。

**放置時：** 多数決で確定した相談先を、落選候補が事後に止められる。受入条件に「確定後の勝者辞退」と「確定後の敗者辞退」を分けた例が必要。

## 2. P1：返金予約後の入金取消で、不要になった予約を精算できない

**根拠：** S:318〜322、S:333、S:372、S:407。確定バッチの未払い額は減らさず、取消後の重みは次のバッチへ反映する一方、実行時には最新の返金権利を照合する。既予約・未送金分の権利が入金取消でなくなった場合に、予約を相殺・終了させる遷移がない。返金指示の状態一覧（S:309）にも、この終了理由がない。

**具体例（手数料・他の債務なし）：**

| 順序 | 現金と予約 |
|---|---|
| AとBが各100円拠出 | 現金200円 |
| 第1バッチ100円を確定 | Aへ50円、Bへ50円を予約。まだ未送金 |
| Aの元入金100円が取り消され、Aへ戻る | 現金100円。Aの有効拠出は0円。予約合計100円なので全体の不足判定だけでは止まらない |
| Aへの追加50円は最新権利の照合で拒否、Bへ50円返金 | 現金50円、Aの未処理予約50円が残る |
| Bの残り50円を返そうとする | `refundAvailable = max(0, 50 - 50) = 0`。Aの予約が拘束し続ける |

過払い防止の照合を守っても、取消済みのAの予約を消せず、Bへの残額返金を妨げる。これは現実の送金で観測した不具合ではなく、記載された状態と計算式による反例である。

**最小修正：** 確定バッチの履歴は保存したまま、署名付き入金取消を根拠に、未実行の返金指示を相殺して予約を解消する追記仕訳と終了状態を定義する。送金済み・未送金・結果不明を分け、結果不明の指示は外部照合前に解放しない。誰が承認し、他の参加者の返金原資へいつ戻せるかまで受入条件にする。

**放置時：** 原資が足りている募集でも一部の返金が止まる。固定バッチを無条件で実行する修正では過払いになるため、単に権利照合を外してはいけない。

## 3. P2：無関係な案件の確定が3回重なると、正常な申請も失効する

**根拠：** S:216〜218。すべての案件で共通のカタログ版を使い、版競合が3回発生すると期限切れになる。無関係な更新でも3/5の再署名が必要で、競合回数から除外する規定はない。

**具体例：** 4件の無関係な案件P・Q・R・Sを同じ版で審査する。Pが先に確定するとSの版比較が失敗する。Sが再署名を集める間にQが確定し、もう一度集める間にRが確定すると、Sは3回目の競合で失効する。重複も入力不備もなく、12日の上限前でも再申請になる。

**最小修正：** 無関係な更新を確認できた場合は3回失効の対象から外し、再照合を継続できる状態にする。最新の版との原子的な比較・書込みは維持する。案件数が増える段階では、確定待ちの申請が繰り返し追い越されない順序も必要。

**放置時：** 案件が増えるほど、正常な申請をやり直す頻度が上がる。4件同時の確定を、将来の受入例に追加する。

## 4. P2：READMEのローカル起動手順では認証を通過できない

**根拠：** `web/README.md:12` はBasic認証の2変数だけを指定する。変更後の `web/src/proxy.ts:13` は別の32文字以上の `AUTH_SESSION_SECRET` を必須とし、`web/src/lib/auth.server.ts:25` はFirestoreのプロジェクトとデータベース設定も要求する。

**具体例：** 追加の環境変数を持たない開発者が記載コマンドを実行すると、最初のリクエストは503になる。セッション秘密だけ追加しても、認証ヘッダーを送るとFirestore設定不足で503になる。前提条件の省略による失敗であり、設定がそろった稼働環境の障害は確認していない。

**最小修正：** 開発用のセッション秘密、Firestoreエミュレーターまたは開発用データベース、その接続設定をREADMEに追加する。本番の秘密をローカル例へ貼り付けず、設定不足を拒否する現在の認証処理は維持する。

**放置時：** 新しい端末や担当者がREADMEだけでデモを起動・確認できない。
