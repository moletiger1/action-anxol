## 1. P1：保存中に戻ると編集中の下書きが消える

- 場所：`web/src/components/groupB/ReviewStep.tsx:124`、同`:133`。
- 再現：保存済み作成例を編集 → 必須事項と確認チェックを満たす →「この作成例を更新する」→ 直後に「戻る」→「その他に相談したいこと」を変更する。
- 実際：1.2秒後に戻り先のフォームが初期記入例へ戻る。追加した文章も消え、相談費設定や公表資料URLも初期値になる。履歴には更新ボタンを押した時点の古い内容が保存される。
- 原因：アンマウント後も `setTimeout` が動き、古い `draft` を保存して共有下書きへ無条件に `reset()` する。
- 修正案：ローカル保存に不要な1.2秒の待機を削除する。将来非同期保存にする場合は、保存対象と現在の下書きが同じときだけ消去する。

## 2. P2：確認後に内容を変更しても確認済みのまま

- 場所：`web/src/components/groupB/draft.ts:193`、`web/src/components/groupB/ReviewStep.tsx:117`。
- 再現：公開確認の2項目にチェック →「戻る」→「その他」を選択し文章を追加 → 公開確認へ進む → 保存する。
- 実際：2項目ともチェック済みのまま。変更後の個人情報・事実と推測の区別を再確認せずに保存できることをE2Eで確認した。
- 原因：`update()` が本文等を変更しても `confirmPii` / `confirmFacts` を保持する。
- 修正案：公開対象の項目が実際に変わったら、共通の下書き更新処理で2つの確認を解除する。確認チェック自身の変更や単なる画面移動では解除しない。
- 補足：保存済みプレビューを「内容を編集する」で開いた直後は、両チェックが解除されることを確認した。不具合はその後の戻る・編集操作にある。

## 3. P3：募集条件のエラーで無関係なチェック欄にフォーカスする

- 場所：`web/src/components/groupB/ErrorSummary.tsx:22`、`web/src/components/ui/Field.tsx:29`。
- 再現：相談費の募集条件を設定する選択肢を選び、5項目を空欄のまま「次へ」を押す。
- 実際：エラー5件は表示されるが、フォーカス先は先頭の対象者チェック欄。目標額などの不正な入力欄へ移らない。DOMの `document.activeElement` と `aria-invalid` で確認した。
- 原因：共通の `TextField` のエラーには `role="alert"` がなく、`focusFirstError()` はページ下のエラー要約を拾い、その親にある最初の入力欄を選ぶ。
- 修正案：`main` 内の最初の `[aria-invalid="true"]` の入力要素を優先してフォーカスする。
