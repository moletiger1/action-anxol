# タイムズカー情報漏えい：共同請求を支援するWebアプリの方針案

位置付け：本書は第一号案件の証拠・情報収集に関する補足資料。サービス全体の現行方針は [参加者が審議し、資金を共同管理するサービス方針](2026-09-29-community-governance-policy.md) を参照する。本書中の運営・審査・課金等の提案と異なる場合は現行方針を優先する。

作成日：2026年9月29日。目的は、会員が自分の証拠を整理し、弁護士が共同交渉・共同訴訟の可否を判断できる資料を作ること。

対象：ユーザーが提示したタイムズカーの漏えい通知本文により、対象事件を確認した。以下は方針案であり、個別事件の勝訴・受任・賠償額の判断ではない。

### 提示された通知の評価（2026年9月29日追記）

| 項目 | 現時点の記録 |
|---|---|
| 資料 | ユーザーが保存した.eml原本を2026年9月29日に読み取り、ヘッダーと本文全体を確認。原本は変更していない |
| 件名・日時 | 不正アクセスによる個人情報漏えいに関するお詫びとお知らせ／Dateヘッダーは2026年9月28日21:26:30 +0900。Gmail画面の受信時刻表示は9月28日21:26。Dateヘッダーと受信時刻は区別する |
| 差出人・宛名 | 表示上はタイムズカー、本文の送信元はタイムズモビリティ株式会社。宛名は「タイムズカー法人会員 ご担当者様」 |
| 文面で確認できること | 会社が漏えいの発生を告知している。ユーザーはこの法人担当者宛て通知を受信したと申告している |
| 未確定 | ユーザー本人の対象性、具体的な漏えい項目、個人の損害。通知受信だけで免許証画像の流出等を確定しない |

アプリでは「通知を受信したこと」「自分の情報が対象と個別に確認されたこと」「各漏えい項目が確認されたこと」を別の状態にする。この通知は、現段階では「法人担当者宛て通知あり／本人の対象性・項目は要確認」と扱う。個人のメールアドレス等は本方針書に転記しない。

原本の照合記録：証拠ID `E001`。保存場所は `/Users/moletiger/Desktop/不正アクセスによる個人情報漏えいに関するお詫びとお知らせ.eml`、サイズ8,471バイト。読み取り時のSHA-256は `6fa229ee2714152bd8853c526b7771e1bf94f9686fcd41dcd7bfaddcd32410bf`。この値は以後の同一ファイル照合用であり、受領前の改変の不存在や記載内容の真実性を証明するものではない。

認証結果：原本内の `Authentication-Results` には、Google受信側で `dkim=pass`（`mail.timescar.jp`）、`dmarc=pass`、`arc=pass` の記録がある。転送前の受信サーバーにも同ドメインのDKIM・DMARC成功記録がある。送信元ドメインの認証が受信時に成功したことを示す記録として扱う。今回、DKIM署名の暗号学的な独立再検証は行っていない。

本文全体に、ユーザー本人の氏名・会員番号に対応した対象確認や、本人固有の漏えい項目の列挙はない。元メールの省略部分まで読んでも、本人の対象性・免許証画像等の対象性は未確定のままである。

追加確認：ユーザーは「この法人契約で自分も運転者として登録しているか」という質問に「はい」と回答。運転者登録は本人申告として記録し、登録資料による照合と漏えい項目の確認は未了とする。

法人契約の場合は、契約当事者である法人の損害と、運転者・担当者本人の個人情報に関する損害を分ける。法人契約を消費者契約と同一扱いせず、特定適格消費者団体の手続の対象性を別途確認する。一方、法人契約の利用者という理由だけで個人のプライバシー侵害に関する請求候補から除外しない。

出典：[消費者庁・消費者契約法の適用範囲](https://www.caa.go.jp/policies/policy/consumer_system/other/pdf/consumer_system_other_180910_0001.pdf)、[国家サイバー統括室・関係法令Q&A、Q61](https://security-portal.cyber.go.jp/guidance/law-handbook/v2-11.html)

会社への確認文案（未送信）：

>

> 2. 私本人が対象の場合、漏えいが確認された情報項目を具体的に教えてください。運転免許証画像・免許証番号の対象性も、それぞれご回答ください。
> 3. 確認済みの範囲で、私の情報が取得された時期と、保存されていた情報の時点を教えてください。未確認の事項は未確認とお知らせください。
> 4. 個人向け・法人向けの補償や対応の方針、今後の個別連絡の予定があれば教えてください。
>
> 回答を保存したいため、メールまたは書面での回答を希望します。本人照合に必要な手続があれば、安全な方法をご案内ください。

## 1. 法的な進め方と、現時点で分かっていること

### 事件の確認

パーク24の2026年9月28日付第2報は、約660万アカウントの情報取得を確認したと発表している。現会員だけでなく、退会者、入会未完了者、タイムズビジネスサービスの会員等も対象に含む。漏えい項目は人によって異なり、運転免許情報・本人確認書類画像などを含む。同発表では、本件に起因する不正利用は確認されていないとしている。これは会社による発表であり、各参加者の対象性や損害を個別に確定するものではない。

出典：[パーク24・第2報](https://www.park24.co.jp/news/2026/09/20260928-1.html)

### 第一候補：弁護士が参加者から直接受任する共同訴訟

民事訴訟法38条は、権利・義務の共通性、同一または同種の事実上・法律上の原因などを共同訴訟の要件としている。「100人集めれば成立する」といった基準ではない。参加者ごとの権利・証拠・委任を整理し、同じ争点を持つ人をまとめる方針が適する。

出典：[民事訴訟法38条](https://laws.e-gov.go.jp/law/408AC0000000109)

### 第二候補：特定適格消費者団体による被害回復手続

この制度の担い手は認定を受けた特定適格消費者団体であり、被害者の会やアプリ運営者が登録者数だけでその資格を得ることはない。慰謝料には、算定の基礎となる主要事実の共通性に加え、同じ事実上の原因に基づく財産的請求と併せて請求する場合、または事業者の故意による場合などの条件がある。外部からの不正アクセスという事実だけで、事業者の故意が認められるわけではない。本件への適用を前提にせず、団体に検討を依頼する選択肢として残す。

出典：[消費者庁・制度と改正](https://www.caa.go.jp/policies/policy/consumer_system/consumer_court_proceedings)、[令和4年改正法・3条2項6号](https://www.sangiin.go.jp/japanese/joho1/kousei/gian/208/pdf/s0802080412080.pdf)、[認定団体の紹介・窓口](https://cocolis.caa.go.jp/introduction/)

弁護士による共同交渉や和解も出口として残す。登録は提訴・委任・和解への同意を意味しない。

### 訴訟判断に必要なもの

会員側の資料で明らかにするのは、誰の、どの情報が対象で、何が起き、どのような損害を申告しているか。会社の注意義務違反や契約上の義務違反、損害との因果関係、被告となる法人は別途検討が必要になる。漏えい発生から過失・賠償義務を自動判定しない。契約相手と情報管理主体を調べ、親会社であることだけを理由にパーク24を被告に固定しない。

金銭被害がなくてもプライバシー侵害に基づく精神的損害が検討対象となる。金銭被害ゼロを参加拒否の理由にしない。具体的な認容額は事実関係によって異なり、本件について一律の金額を表示しない。

出典：[国家サイバー統括室・関係法令Q&A、Q61](https://security-portal.cyber.go.jp/guidance/law-handbook/v2-11.html)

## 2. 会員から集める情報

### 初回登録：入力目標3分

| 分類 | 入力内容 | 必須性と用途 |
|---|---|---|
| 連絡先 | 連絡用メールアドレス、メール認証 | 必須。タイムズの登録アドレスと同じである必要はない。認証は連絡先の確認であり、被害者本人の確認とは区別する |
| 会員との関係 | 現会員／退会済み／入会未完了、サービス名、個人契約／法人契約／不明、法人の場合は運転者・管理担当者を複数選択可、入退会のおおよその年月 | 状態と区分は必須、日付は不明可。契約主体と個人の立場を整理する |
| 漏えいの確認 | 通知あり／問い合わせ回答あり／報道だけ／未確認、通知の宛名区分、通知受領日、本人の対象性、通知に書かれた漏えい項目 | 確認状態は必須。本人の対象性と各項目は「対象と明記／対象外と明記／不明」で別々に記録し、通知の受信や総論から本人・全項目の漏えいを推定しない |
| 被害の概要 | 金銭支出、不審連絡、なりすまし、生活への影響について、それぞれあり／なし／不明 | 回答必須、詳しい説明は後から。金銭被害と精神的影響を別項目にする |
| 参加意向・同意 | 情報提供のみ／弁護士相談希望／条件を聞いて訴訟検討、収集目的・運営主体・保管方針の確認 | 登録目的を明示。第三者提供、訴訟委任、対外公表への同意は別にする |

登録完了時に、事件固有の受付IDと自分の回答控えを渡す。「情報登録済み」と表示し、「原告登録完了」とは表示しない。

### 証拠整理：資料が手元にある場合の入力目標10〜15分

| 分類 | 集める情報・証拠 | 判断に役立つ点 |
|---|---|---|
| 契約・対象性 | 個別通知、入会・退会メール、会員ページ、請求書等。送信者、受信日、契約主体、通知番号も記録 | その人と事故・契約との結び付き。退会者や法人利用者も分けて検討できる |
| 金銭的な損害 | 支出日、金額、目的、必要になった理由、領収書、返金・保険補填の金額と状況 | 申告額と補填済み額を区別し、必要性・因果関係を審査する。対応時間は時間として記録し、自動で時給換算しない |
| 二次被害と時系列 | 不審連絡・不正利用等の発生日、内容、相手が知っていた情報、保存したメールやSMS、事故前にもあったか、他の漏えい通知の有無 | 本件との関連を検討する。事故後に起きただけで本件が原因と断定しない。別サービスのパスワード等は収集しない |
| 精神面・生活への影響 | 本人の言葉で、何が不安か、いつからか、継続期間、実際の生活変化、対応内容 | 定型文で苦痛を誘導しない。「影響なし」「答えたくない」も選べる。診断書等は初期アプリでは集めず、必要なら弁護士が別途扱う |
| 会社対応・解決状況 | 問い合わせ日時と回答、補償提案、受領済み補償、同意した文言、和解・請求放棄に関する書面、他の弁護士への依頼状況 | 未解決部分と重複依頼を確認。補償受領だけで一律に請求不可と判定しない |

全項目で「本人の申告」「証拠で確認」「弁護士確認済み」を分ける。申告額は請求可能額・裁判所認定額とは表示しない。

### 受任段階：弁護士の管理下で追加収集

本名、送達等に必要な住所、本人・会員の照合情報、必要な連絡先、利益相反確認に必要な事項、委任状、費用説明への同意を収集する。本人確認方法は担当弁護士と決める。免許証画像や免許証番号全文を初回登録の必須条件にしない。マイナンバー、タイムズのパスワード、認証コード、クレジットカード番号は集めない。

## 3. 証拠の扱いと、会社側について調べること

### 証拠保存の最小要件

1. 参加者には元メール・元ファイルを手元に保管してもらう。メールは可能ならヘッダー付きで保存し、スクリーンショットだけに依存しない。
2. アプリには必要部分をマスキングした写しを提出できるようにする。無加工原本を受け取る場合は弁護士専用の制限された保管先を使う。マスキング済み写しと原本を混同しない。
3. 証拠ごとに受付ID、提出者、取得元、取得日時、提出日時、ファイル名、対応する申告を記録する。受領後の変更を確認するハッシュと変更履歴を残す。ハッシュだけで内容の真実性を証明できるわけではない。
4. 発生日・受信日と、アプリへの入力日を別にする。訂正は履歴を残し、本人が訂正内容を確認できるようにする。
5. 弁護士には、個人ごとの時系列、証拠一覧、損害内訳、同意状態をCSV/PDFと証拠ファイルで渡せるようにする。単独のZIP出力を無制限に許可せず、受領者・対象・出力日時を記録する。

### 運営側で一度集める共通資料

会員全員に同じ調査をさせず、公式発表と更新履歴、当時の規約・プライバシーポリシー、公開された調査報告、会社から得られた回答を出典付きで保存する。

弁護士が追加検討する論点は、侵入原因と対策、情報管理・委託の実態、退会後を含む保管の目的・期間、通知と対応、各法人の関与。退会者の情報が残っていた事実だけで違法と断定しない。非公開資料が必要なら、弁護士が照会や訴訟上の手段、証拠保全の必要性を検討する。

漏えいデータそのものを取得・購入して本人確認に使う設計は採らない。アプリ登録が時効の完成を防ぐ手続であるとは案内しない。期限の確認と必要な法的措置は弁護士に引き継ぐ。

## 4. 最初に作るアプリと運営条件

最初の版は次の5機能に絞る。

1. **非公開の登録フォーム**：連絡先認証、途中保存、本人による訂正、受付IDの発行。
2. **証拠整理ページ**：資料の有無、必要な写し、被害の時系列を整理。原本提出が必要なら弁護士の既存保管先につなぐ。
3. **確認状況の管理画面**：個人契約・法人利用、現会員・退会等、漏えい項目、証拠確認状況、損害種別で絞り込む。法的資格や勝率を自動判定しない。
4. **弁護士への引継ぎ**：提供先を指定した同意、資料の出力、担当者と引渡し履歴。委任は別の手続とする。
5. **本人向け進捗表示**：登録済み／資料確認中／相談案内／委任手続など、現実の状態を表示する。提訴済み表示は実際の提訴後に限る。

公開画面には運営者と問い合わせ先、確認済みの事実、活動方針を掲載する。公開人数を出す場合は、登録数・資料確認数・受任数を区別する。少人数の属性別集計や個別エピソードは公開しない。

### 個人情報を扱うための条件

収集前に利用目的・運営責任者・閲覧権限・保存と削除の方針を示す。アプリ利用の同意と、特定の弁護士・団体への提供同意を別に記録する。医療情報等を扱う場合は要配慮個人情報の扱いを別途設計する。

出典：[個人情報保護委員会・通則ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)

設計案として、管理者は多要素認証、担当者以外の閲覧を制限し、証拠ファイルは非公開保管・通信と保存の暗号化・期限付きダウンロードを使う。閲覧・出力履歴を残し、ファイルの種類・容量制限と安全なプレビューを用意する。広告トラッカーや外部AIへの証拠送信は初期版に入れない。

保存期間案：登録後90日で本人に継続希望を確認し、30日間応答がなければ削除を事前通知する。受任済み・紛争対応中の証拠は担当弁護士の保存方針を適用し、自動削除しない。本人からの削除相談、エクスポート済み資料、バックアップの削除期限まで運用を決める。この期間は法定期限ではなく、公開前に弁護士と確定する設計値。

### 運営者と弁護士の役割

運営者は情報整理とシステム提供を担当し、個別の法律判断・相手との代理交渉・訴訟受任は弁護士が担当する。初期版は参加者への請求、紹介料、回収額連動報酬を設けない。将来の収益化は弁護士法72条等との関係を確認してから決める。無料であることだけを適法性の根拠にはしない。

出典：[弁護士法72条](https://laws.e-gov.go.jp/law/324AC1000000205)

## 5. 実行順序と、提訴検討に進む基準

1. **ユーザー自身の1件を整理する。** 個別通知の有無、会員区分、漏えい項目、損害・問い合わせの有無を上記様式でまとめる。資料が手元にあれば10〜15分を目標とする。
2. **弁護士の初回相談用資料にする。** 本方針、個人が分からない形のサンプル、公式発表を使い、請求構成、相手方、証拠の不足、費用体系、データ管理主体を相談する。資料の送信は本人の指示・同意後に行う。
3. **少人数で入力を試す。** 協力者5〜10人を運用上の試行目安とし、項目の分かりにくさ・証拠不足を確認する。この人数は法的条件ではない。実データの収集は運営主体と管理方法の確定後に行う。
4. **公開募集に進めるか判断する。** 担当弁護士または相談先、受け渡す資料の形式、個人情報の扱い、費用の説明が具体化した時点で公開する。受任していない弁護士・団体を提携先として表示しない。
5. **本人ごとに参加を確定する。** 弁護士の見立てと費用を示し、参加者が委任を選ぶ。交渉・提訴・和解は、その内容と権限を確認して進める。

提訴検討に進むための成果物は、対象性を裏付けた参加候補者名簿、共通争点と必要に応じたグループ分け、会社側の責任に関する証拠と未解明点、個人別の損害・証拠・補填状況、費用と参加意思の記録。登録人数や申告総額だけで「提訴可能」とは判断しない。
